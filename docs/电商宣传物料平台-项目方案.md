# 电商宣传物料 AI 工作台（视频优先）· 项目方案

> 版本：v1.2　日期：2026-10-22　状态：方案定稿 / v0.2 已实现（DeepSeek + REST 图片/视频）
>
> 技术栈：Vue 3 全家桶 + Python FastAPI + SQLite + 火山方舟（豆包 / Seedream / Seedance）

---

## 摘要

这是一个**本地运行、单用户**的电商内容生产工作台。用户上传产品图、填写商品描述，系统先理解商品，再根据商品品类、平台与营销目标推荐**视频风格 Skill**，按 Skill 自动生成脚本与分镜，先产出低成本的**预演小样**，确认后调用 Seedance 逐镜生成视频，最后由本地媒体管线完成字幕、拼接、封面与平台适配，导出可直接投放的成片与配套文案。

与"再做一个 AI 生图按钮"不同，本产品的核心资产是**可版本化的视频风格 Skill**：它同时约束叙事节拍、镜头语言、Prompt、字幕样式、音频策略与质检标准，使"同一个商品"可以稳定产出抖音、小红书、闲鱼、淘宝等不同平台需要的视频表达。

首版（v0.1）以 **Mock 模式**保证无 API Key 也能完整跑通并产出可播放 MP4；真实方舟适配器同构实现，待账号与 Key 就绪后切换 `AI_MODE=real` 联调。

## 1. 背景与机会

### 1.1 市场背景

- 短视频与直播已成为电商成交的主入口，商品主图视频、种草视频、直播切片、信息流素材的需求量远高于传统详情页。
- 中小商家普遍缺少编导、摄影、剪辑与投放素材团队；外包一条 15–30 秒成片的成本与周期都难以规模化。
- 平台自带工具在快速进化。例如抖音电商学习中心已提供「AI 做主图」「AI 智能成片」等能力，说明"单点生成"正在成为基础设施。
- 生成模型能力已跨过可用门槛：Seedance 2.5 支持 30 秒长叙事与两次延长、精准参考与编辑；Seedance 2.0 支持文字/图片/音频/视频四种模态输入与原生音画同步；Seedream 4.0 支持 4K、多图组合与批量输出；Seedream 5.0 Pro 进一步支持高密度信息、图层拆分与多语种。

### 1.2 商家真实痛点

1. **不知道拍什么**：有产品，没有脚本；有卖点，不会转成 3 秒钩子。
2. **拍不起/拍不快**：模特、场地、灯光、摄影、剪辑，任何一项都拖慢上新。
3. **平台表达不同**：抖音要强钩子，小红书要真实种草，闲鱼要个人化，淘宝要卖点前置，一条片子改五版。
4. **一致性难保证**：AI 生成容易把商品"改款"，颜色、结构、Logo 失真，产生虚假宣传风险。
5. **素材不可追溯**：不知道用了哪个模型、哪版 Prompt、花了多少钱，无法复用与审计。
6. **合规风险**：极限词、功效宣称、AI 内容标识，一旦踩线就是下架或处罚。

### 1.3 差异化定位

| 维度 | 平台自带工具 | 通用 AI 视频工具 | 本产品 |
|---|---|---|---|
| 跨平台 | 单平台 | 需手工改写 | 一套 Brief 生成多平台表达 |
| 脚本能力 | 模板化 | 通用聊天 | **Skill 化脚本 + 分镜规范** |
| 商品一致性 | 一般 | 弱 | 关键帧驱动 + 商品锁定 + 质检 |
| 成本控制 | 不透明 | 按次 | 预演先行 + 草稿/终版 + 预算闸门 |
| 数据归属 | 平台云 | 厂商云 | **本地 SQLite + 文件** |
| 可追溯 | 弱 | 弱 | Prompt/模型/种子/成本/版本全记录 |
| 合规 | 平台规则 | 无 | 极限词 + 功效 + AIGC 标识 |

## 2. 产品定位与目标

### 2.1 一句话

**把一段商品描述，变成一套能直接发的电商短视频。**

### 2.2 目标用户

- 中小电商商家、个体卖家、工厂型商家。
- 代运营/内容工作室（一个人服务多个店铺）。
- 需要快速测试素材的投放优化师。

### 2.3 成功指标

**北极星指标**：每周产出的"可直接发布"成片数量。

辅助指标：

- 从新建项目到首条成片的中位时长（目标 < 15 分钟，含人工确认）。
- 单条成片的一次通过率（无需重生成镜头）。
- 商品一致性评分 ≥ 4/5 的比例。
- 文案/脚本人工修改率。
- 单条成片综合成本（图片 + 视频 + 文本）。
- 7 日内复用同一商品再次生成的比例。

### 2.4 产品边界

- **只做内容生产**，不做店铺授权、自动发布、投放托管。
- **只做本地单用户**，不做多租户与计费。
- **不做数字人与口型同步**（首版），避免肖像权与"虚假真人"风险。
- **不改商品本体**：AI 只改变环境、光影、构图与镜头语言。

## 3. 用户与场景

### 3.1 角色

| 角色 | 目标 | 关键动作 |
|---|---|---|
| 商家老板 | 快速上新、测款 | 上传图、选风格、看成片、导出 |
| 运营 | 多平台铺内容 | 一套 Brief 出多平台版本、改文案 |
| 内容代运营 | 批量交付 | 多项目、复用 Skill、控制成本 |
| 投放优化师 | 快速做素材 | 生成多版本钩子、封面、标题 |

### 3.2 典型场景

**场景 A：家居清洁新品**
上传 3 张产品图，描述"厨房油污清洁剂，500ml，植物配方，不伤手"。系统推荐「痛点反转」，生成 5 镜 15 秒脚本：油污痛点 → 喷一喷 → 擦拭对比 → 成分说明 → 下单利益点。预演确认后出片，导出抖音 9:16 与小红书 3:4 两版。

**场景 B：食品工厂溯源**
上传产线/原料图，描述"云南小粒咖啡，日晒处理，中度烘焙"。系统推荐「工厂溯源」，生成产地、晾晒、烘焙、杯测、冲泡五个镜头，字幕强调工艺，避免绝对化用语。

**场景 C：闲鱼二手数码**
上传成色图，描述"自用 iPad，95 新，无磕碰，配件齐全"。系统推荐「个人化实拍」，生成短平快的 15 秒视频与闲鱼描述，语气真实、突出低价理由与同城交易。

### 3.3 用户旅程

```
上传/描述 → AI 理解 → 选风格 → 改脚本 → 看预演 → 出终版 → 导出/发布 → 复用
   1min       10s       30s       2min      2min      5min      30s
```

## 5. 视频风格 Skill 体系

### 5.1 什么是 Skill

Skill 不是一段 Prompt，而是一份**可版本化的视频配方**，包含：

- 适用条件：平台、时长、画幅、品类、价格带、目标。
- 叙事结构：beats（钩子/痛点/揭示/证据/行动），每个 beat 的目标与时长。
- 分镜规范：镜头数、单镜时长、景别、运镜、转场、商品露出比例。
- 视觉规范：风格、光线、色板、场景、负向词、商品锁定句。
- 音频规范：原生音效 / TTS 口播 / 混合，BGM 情绪。
- 字幕规范：样式、位置、每行字数、安全区。
- 质检项：商品一致性、钩子清晰度、字幕安全区、合规。

### 5.2 YAML Schema

```yaml
id: pain_point_reversal          # 唯一 slug
name: 痛点反转
category: conversion             # brand | seeding | conversion | demo
goal: 转化
version: 1
platforms: [douyin, xiaohongshu]
durations: [15, 30]
ratios: ["9:16"]
suitable_categories: [家居, 清洁, 小家电, 母婴]
not_suitable: [高客单耐消]
beats:
  - { id: hook,    seconds: 3, purpose: "3 秒抛出痛点或反常识" }
  - { id: problem, seconds: 3, purpose: "放大痛点，建立共鸣" }
  - { id: reveal,  seconds: 4, purpose: "产品出场，给出一击" }
  - { id: proof,   seconds: 3, purpose: "演示/对比/证据" }
  - { id: cta,     seconds: 2, purpose: "利益点 + 行动指令" }
shots:
  min: 4
  max: 6
  seconds: [3, 5]
  product_visible_ratio: 0.6
  presenter: none
prompt:
  style: "真实生活质感，自然光，轻微手持感，电商广告级清晰度"
  lighting: "窗边侧逆光，柔和阴影"
  palette: ["#F6F1E7", "#E8D9C5", "#2E2A26"]
  camera: [特写推近, 中景跟拍, 俯拍旋转, 固定机位]
  negative: "变形, 多余部件, 错误文字, 水印, 低清晰度, 过曝"
  product_lock: "严格保持商品的外形、比例、颜色、材质、Logo、结构和文字不变；不得增删部件"
subtitle:
  style: bold_yellow
  position: lower_third
  max_chars_per_line: 12
audio:
  mode: none                     # none | native | voiceover | mixed
  bgm_mood: upbeat
```

### 5.3 首版 Skill 库

| ID | 名称 | 目标 | 适用品类 | 结构要点 | 优先级 |
|---|---|---|---|---|---|
| pain_point_reversal | 痛点反转 | 转化 | 家居/清洁/小家电/母婴 | 痛点→放大→产品→证据→CTA | P0 |
| unboxing_review | 开箱测评 | 种草 | 3C/美妆/食品 | 开箱→细节→实测→结论 | P0 |
| product_closeup | 产品特写/ASMR | 种草 | 食品/香氛/饰品 | 微距、材质、声音、光影 | P0 |
| lifestyle_scene | 场景生活方式 | 种草 | 家居/服饰/户外 | 生活片段→产品自然入镜 | P0 |
| factory_origin | 工厂/源头溯源 | 信任 | 食品/农产品/日用品 | 产地/产线→质检→成品 | P1 |
| tutorial_howto | 教程干货 | 收藏 | 美妆/工具/母婴 | 步骤 1-2-3→效果→CTA | P1 |

后续扩展：对比实验、节日促销、榜单盘点、品牌 TVC、直播切片、买家证言、3D 白模演示、街头采访、换装改造。

### 5.4 推荐算法

首版使用规则打分，避免为推荐额外消耗模型额度：

```
score = 0.40 * 品类匹配
      + 0.30 * 目标匹配（种草/转化/品牌）
      + 0.20 * 平台/时长兼容
      + 0.10 * 价格带/调性匹配
```

输出 Top3 与一句理由；无匹配时回退到 `pain_point_reversal`。后续可加入"历史完播/转化"反馈做 Learning to Rank。

### 5.5 版本与评测

- Skill 有独立版本号；脚本记录 `skill_id + skill_version`。
- 每次生成记录：镜头数、重试次数、人工修改率、导出率、人工评分。
- 新版本上线前用固定商品集做回归，避免"改一个 Skill 崩一批商品"。

## 6. 视频生产流水线

### 6.1 DAG

```
ProductBrief
   │
   ├─► Skill 推荐 ──► VideoScript(JSON) ──► 预演小样 ──► 用户批准
   │                                            │
   │                                            ▼
   └──────────────────────────────► StyleBible + 逐镜关键帧（Seedream）
                                                │
                                                ▼
                                     逐镜视频（Seedance）
                                                │
                                     质检/重试（时长/黑帧/一致性）
                                                │
                                     合成（FFmpeg：拼接/字幕/混音）
                                                │
                                     平台变体 + 封面 + 文案
                                                │
                                             ZIP 导出
```

### 6.2 各阶段说明

| 阶段 | 输入 | 输出 | 失败处理 |
|---|---|---|---|
| S0 商品理解 | 图片 + 描述 | ProductBrief | 图片模糊则提示重拍；描述不足则追问 |
| S1 风格推荐 | Brief + 平台/目标 | Top3 Skill | 无匹配回退默认 |
| S2 脚本 | Brief + Skill | VideoScript + Shots | JSON 校验失败自动修复/重试 |
| S3 预演 | Shots + 商品图 | 关键帧 + animatic | 单镜重生成；可改文案 |
| S4 关键帧定稿 | 批准的 Shots | 每镜首帧 | 商品一致性低则重试 |
| S5 逐镜视频 | 首帧 + Prompt | 每镜 MP4 | 单镜重试 ≤2；可跳过 |
| S6 合成 | 全部镜头 | 成片 MP4 | 拼接失败降级重编码 |
| S7 变体/导出 | 成片 + 文案 | ZIP/封面/SRT | 缺件则阻断导出 |

### 6.3 镜头状态机

```
pending
  → keyframe_running → keyframe_ready
  → video_running    → video_ready
  → qa_passed | qa_failed
  → retry (≤2) | skipped
```

每个状态变更都落库；服务重启后扫描 `running` 转 `queued`，保证断点续跑。

### 6.4 预演、草稿与终版

- **预演（previs）**：关键帧 + 缓慢推拉 + 字幕 + 可选 TTS，低清快速，成本约为终版的 10%。
- **草稿（draft）**：480p、少镜头、短时长，用于验证叙事。
- **终版（final）**：1080p、完整镜头、完整音频。
- 默认流程必须先预演、后终版；跳过预演需二次确认。

### 6.5 商品一致性策略

1. **关键帧先行**：每镜先生成首帧，商品锁定 Prompt + 参考图。
2. **StyleBible 统一**：色板、光线、镜头语言、场景、负向词一次生成，注入所有镜头。
3. **图生视频**：以首帧作为视频起点，减少模型自由发挥。
4. **抽帧质检**：VLM 对成片抽帧与原图比对，评分 < 4 触发重试。
5. **人工兜底**：结果页展示"原图 / 关键帧 / 成片帧"对比，允许单镜替换。

### 6.6 音频与字幕

- **音频双轨**：`native`（Seedance 原生音效/环境声）、`voiceover`（TTS 口播）、`mixed`；首版为 `none`，只保留静音轨。
- **字幕**：Pillow 渲染透明 PNG，FFmpeg overlay 烧录；不依赖 libass，中文排版可控，同时导出 SRT。
- **安全区**：底部 18%、左右 8% 内不放关键信息；平台 UI 遮挡区域在 presets 中配置。
- **响度**：终版做 `loudnorm`，目标 -14 LUFS（短视频平台常用）。

## 7. 平台策略

### 7.1 平台表达差异

| 平台 | 用户意图 | 内容风格 | 首版物料 | 默认画幅/时长 |
|---|---|---|---|---|
| 抖音 | 兴趣/冲动 | 3 秒钩子、强节奏、口播、利益点前置 | 成片 + 封面 + 标题/话题 + 分镜 | 9:16 / 15–30s |
| 小红书 | 种草/决策 | 真实体验、人设、干货、避坑 | 成片 + 3:4 封面 + 笔记正文/标签 | 9:16 或 3:4 / 15–60s |
| 闲鱼 | 二手/低价 | 个人化、真实、低价理由、同城 | 成片 + 1:1 封面 + 描述 | 1:1 或 3:4 / 15–30s |
| 淘宝/天猫 | 搜索/比价 | 卖点前置、静音可看、信任背书 | 主图视频 + 封面 + 卖点 | 1:1 或 3:4 / 9–30s |
| 拼多多 | 价格敏感 | 直白、促销氛围、利益点 | 成片 + 封面 + 促销文案 | 1:1 / 9–30s |
| 视频号 | 社交推荐 | 完播率、生活感 | 成片 + 封面 + 标题 | 9:16 / 15–60s |
| B 站 | 深度内容 | 信息密度、横屏 | 成片 + 横版封面 | 16:9 / 30–120s（P2） |

> 以上为产品预设，像素级限制以平台最新规则为准；所有规格放在 `presets/platforms.yaml`，不写死在代码。

### 7.2 变体规则

- 同一脚本生成 9:16 / 3:4 / 1:1 三个版本时，**重新排版字幕与安全区**，不做简单裁切。
- 横屏版本重排镜头构图，避免主体被裁。
- 时长变体优先删减 `problem` 与 `proof` 镜头，保留 `hook/reveal/cta`。

### 7.3 导出规范

```
{项目名}/{平台}/{日期}_{版本}/
  final_9x16_15s.mp4
  cover_9x16.jpg
  script.json
  subtitles.srt
  caption.md
  manifest.json
```

- MP4：H.264 / yuv420p / 30fps / AAC 128kbps / `+faststart`。
- 封面：JPG，与成片同画幅。
- manifest：模型、模式、Skill 版本、镜头表、耗时、成本、合规结果、AI 标识。

## 8. 技术架构

### 8.1 架构图

```
Vue 3 + TypeScript + Element Plus
        │ REST（轮询任务进度）
FastAPI（127.0.0.1:8000）
  ├─ API 层：项目/商品/脚本/镜头/任务/导出
  ├─ JobRunner：asyncio 后台任务（测试可同步）
  ├─ Skill 引擎：YAML 载入、校验、推荐
  ├─ Script 引擎：Mock 模板 / LLM JSON
  ├─ 媒体层：Pillow（关键帧/字幕/封面）+ FFmpeg（片段/拼接/音频）
  ├─ Provider：Mock / ArkChat / ArkImage / Seedance
  ├─ 合规引擎：极限词、功效、平台规则
  └─ SQLite（WAL）+ data/ 本地文件
        │ HTTPS（仅 real）
   火山方舟 API
```

### 8.2 技术选型

| 层 | 选型 | 理由 |
|---|---|---|
| 前端 | Vue 3.5 + Vite 8 + TypeScript 5.9 + Pinia 3 + Vue Router 4 + Element Plus 2.14 | 全家桶、组件成熟、上手快 |
| 后端 | Python 3.12 + FastAPI 0.159 + SQLAlchemy 2.1 + Pydantic 2 | 异步、类型化、生态好 |
| 数据库 | SQLite（WAL） | 单用户零运维，备份即文件 |
| 图像 | Pillow 13 | 关键帧、字幕、封面确定性渲染 |
| 视频 | FFmpeg（imageio-ffmpeg 0.6 内置二进制） | 本机无 ffmpeg，pip 包自带，免安装 |
| AI | 火山方舟 REST（httpx 直连） | 不绑定 SDK，便于 Mock/换供应商 |
| 测试 | pytest + FastAPI TestClient | 服务级 + API 级 |
| 部署 | 单进程 uvicorn + 静态文件 | Windows 本地双击启动 |

### 8.3 本机环境事实

- Node 24.19.0；pnpm 11.28.5（`pnpm.ps1` 被执行策略拦截，统一用 `node <pnpm.mjs>`）。
- Python 3.12.10；pip 25.0.1；PyPI 可用。
- 未安装 FFmpeg；使用 `imageio-ffmpeg` 的 Windows 二进制。
- 未安装 Git；首版不初始化仓库，只提供 `.gitignore`。
- 无 `ARK_API_KEY`；v0.1 默认 `AI_MODE=mock`。

### 8.4 并发与任务

- 文本/图像/视频分别设置信号量；视频默认并发 2，避免额度与显存/带宽压力。
- 任务表落库，前端 1–2 秒轮询；v0.2 增加 SSE。
- 幂等键：`hash(project_id + stage + script_version + shot_idx + prompt + model + seed)`，防重复扣费。

## 12. 前端设计

### 12.1 信息架构

| 路由 | 页面 | 核心内容 |
|---|---|---|
| `/` | 工作台 | 新建入口、统计、最近项目 |
| `/projects/new` | 新建向导 | 商品 → 风格 → 脚本 → 生成 |
| `/projects/:id` | 项目详情 | 成片、分镜、关键帧、导出 |
| `/skills` | 风格库 | 6 个 Skill 卡片与详情 |
| `/tasks` | 任务中心 | 生成任务、进度、错误 |
| `/settings` | 设置 | 模式、模型、Key 状态、FFmpeg、数据目录 |

### 12.2 新建向导

1. **商品资料**：项目名、描述、价格、图片上传、AI 解析、Brief 编辑。
2. **风格推荐**：平台/时长固定为抖音 15s；Top3 卡片（名称、适用、镜头数、理由）；展开全部风格。
3. **脚本分镜**：标题、发布文案、镜头卡片（场景/运镜/口播/字幕/秒数），总时长指示。
4. **生成**：预演进度 → 关键帧网格 → 终版进度 → 播放器 → 导出。

### 12.3 项目详情

- 顶部：成片播放器 + 封面 + 平台信息 + 导出按钮。
- 中部：镜头时间线（缩略图、口播、字幕、状态、单镜重生成）。
- 右侧：合规提示、manifest 摘要、版本信息。
- 空态：若只有脚本，显示"生成预演"；若只有关键帧，显示"生成成片"。

### 12.4 交互原则

- 生成是非阻塞任务，离开页面不中断；任务中心可回到项目。
- 所有编辑自动保存草稿；"重新生成"前二次确认。
- 失败项单独重试，不影响已完成镜头。
- 预估耗时/成本在按钮旁展示；超预算需确认。

### 12.5 视觉

- 暖白背景 + 深棕侧栏 + 橙色强调，强调"内容工作室"而非"后台系统"。
- 视频卡片 9:16 竖版比例；关键帧网格 3 列。
- 中文优先，字号不小于 13px；移动端保证可用。

## 13. 成本、性能与可靠性

### 13.1 成本模型

```
单条成本 =
  关键帧数 × 图片单价
+ 镜头数 × 镜头秒数 × 视频单价
+ 文本 tokens × 单价
+ TTS 字符数 × 单价
+ 变体数 × 合成成本
```

- 价格表放 `pricing.yaml`，按方舟账单校准；未配置价格表时禁止 real 模式。
- 单任务预算上限、单日预算上限；超限暂停并提示。
- 预演阶段成本约为终版 10%，默认必须预演。

### 13.2 性能目标

| 阶段 | 目标 |
|---|---|
| 商品解析 | < 10s |
| 脚本生成 | < 20s |
| 5 镜预演 | < 2min |
| 5 镜 1080p 终版 | < 15min（并发 2） |
| 导出 | < 10s |

### 13.3 可靠性

- 任务与镜头状态落库，重启恢复。
- 幂等键防重复扣费。
- 429/5xx 指数退避；超时可取消。
- 媒体文件校验（时长、分辨率、音轨）后才标记成功。
- 日志脱敏：不打印 API Key、Authorization、完整 Prompt 中的敏感信息。

### 13.4 磁盘

- 网页预览用 540p 代理，原片归档。
- 中间片段默认保留 7 天，可配置立即清理。
- 导出包单独目录，不随项目删除自动清理（需确认）。

## 14. 合规、版权与 AI 标识

### 14.1 内容合规

- 广告法极限词：最、第一、顶级、国家级、100%、绝对、唯一、万能、永久等。
- 功效宣称：医疗/保健/化妆品/食品特殊限制。
- 平台规则：抖音/小红书/闲鱼/淘宝/拼多多各自违禁词。
- 对比实验、买家证言类内容必须基于真实素材，并保留证据。
- 不做"AI 换脸真人""虚构销量/评价""伪造资质"。

### 14.2 AIGC 标识

依据《人工智能生成合成内容标识办法》（2025-09-01 施行）：

- 显式标识：成片角标「AI 生成」、片头提示、封面角标。
- 隐式标识：MP4/JPEG 元数据、manifest 生成记录。
- 标识默认开启，可在设置中调整样式，但不能关闭。

### 14.3 版权

- 字体：演示用系统字体；正式发布替换为 OFL/商用授权字体（思源黑体、阿里巴巴普惠体）。
- BGM：仅使用用户导入或 CC0/已授权曲库，禁止抓取平台音乐。
- 用户上传图片需确认拥有使用权；不抓取竞品图。
- 不生成真实人物肖像；虚拟人物需标识。

## 17. 风险与对策

| 风险 | 影响 | 对策 |
|---|---|---|
| 视频生成慢/贵 | 成本失控 | 预演先行、草稿模式、镜头级重试、缓存、预算闸门 |
| 多镜头商品漂移 | 虚假宣传 | 关键帧驱动、商品锁定、StyleBible、VLM 抽帧质检 |
| 音频/口播不可控 | 成片质量 | 音频双轨、TTS 可替换、字幕兜底、不承诺口型 |
| 平台规则变化 | 素材被拒 | presets 配置化、版本化、发布前校准 |
| 合规风险 | 下架/处罚 | 极限词/功效库、人工确认、AIGC 标识 |
| FFmpeg 编码器缺失 | 渲染失败 | 启动探测、mpeg4 降级、健康接口暴露 |
| 磁盘增长 | 空间耗尽 | 代理文件、中间产物清理、导出归档 |
| 长任务中断 | 重复扣费 | 状态落库、幂等键、断点续跑、取消接口 |
| 真实 API 字段差异 | 联调失败 | 适配层隔离、配置化、Mock 契约测试 |

## 21. MCP 视频接入（已实现）

### 21.1 接入方式

- 协议：MCP Streamable HTTP（JSON-RPC 2.0），`Content-Type: application/json`，兼容 `text/event-stream`。
- 鉴权：`Authorization: Bearer <MCP_VIDEO_TOKEN>`。
- 流程：`initialize` → `notifications/initialized` → `tools/call`。
- 服务端不强制 session（实测无 `Mcp-Session-Id`），客户端仍兼容该响应头。
- 实现：`backend/app/services/providers/mcp.py`。

### 21.2 工具契约

| 工具 | 作用 | 关键参数 | 返回 |
|---|---|---|---|
| `video_generate` | 创建视频任务 | `prompt`, `params`, `images[]`, `audios[]`, `wait_seconds` | `job_id`, `status`, `progress`, `inputs`, `results` |
| `generation_job` | 查询/推进任务 | `job_id`, `wait_seconds` | 任务状态、进度、结果列表 |
| `generation_result` | 读取结果 | `job_id` | `results[]`，含 `remote_url` / `download_url` |
| `generation_list` | 历史任务 | `kind`, `limit` | 任务列表（含 provider/model/params） |

### 21.3 视频参数

实测当前 Key 的默认模型为 `gsai / minimax-h3`，参数：

```json
{
  "aspectRatio": "portrait",
  "resolution": "480p",
  "duration": 4
}
```

- `aspectRatio`：`portrait`（9:16 / 3:4）、`landscape`（16:9）、`square`（1:1）。
- `resolution`：首版使用 `480p`，可在 `.env` 调整为 `720p`（以 Key/模型支持为准）。
- `duration`：秒；首版最小 4 秒，短镜头在后期裁切。
- `images`：字符串数组，支持 `data:image/jpeg;base64,...`。第一张作为首帧（无文字场景板 plate），第二张为原始产品图，用于保持商品一致。
- `audios`：预留；首版不传。

### 21.4 生产链路

```
Pillow 场景板 plate（无文字）
  → video_generate(images=[plate, original], params={portrait,480p,4s})
  → generation_job 轮询 → generation_result 取 remote_url
  → FFmpeg normalize：裁到镜头时长、补帧、1080×1920/30fps
  → 叠加字幕 PNG + 「AI 生成」角标
  → 与其余镜头 concat → 封面 → ZIP
```

- 场景板不含标题/字幕，避免图生视频把中文"画"进画面。
- 字幕与 AI 标识始终由 Pillow 生成、FFmpeg 叠加，保证文字准确。
- 商品一致性：plate + 原图双参考 + Prompt 锁定商品外形/颜色/材质/Logo。

### 21.5 配置

| 变量 | 默认 | 说明 |
|---|---|---|
| `VIDEO_PROVIDER` | mock | mock / seedance / mcp |
| `MCP_VIDEO_URL` | 空 | MCP 端点 |
| `MCP_VIDEO_TOKEN` | 空 | Bearer Token，仅 .env |
| `MCP_VIDEO_TOOL` | video_generate | 视频工具名 |
| `MCP_VIDEO_RESOLUTION` | 480p | 生成分辨率 |
| `MCP_VIDEO_DURATION` | 4 | 单镜请求时长（秒） |
| `MCP_VIDEO_TIMEOUT` | 1200 | 任务总超时 |
| `MCP_VIDEO_POLL_SECONDS` | 60 | 单次轮询等待 |

设置页可在 `mock / mcp / seedance` 间切换，并提供「测试 MCP 连接」（只返回工具数量，不回显 Token）。

### 21.6 超时与错误

- 创建任务后每 60 秒轮询一次，总超时 1200 秒。
- 任务 `failed/error/cancelled` 立即失败，错误写入 `generations.error` 与镜头 `shots.error`。
- 结果资产可能先处于 `downloading`，客户端会等待并重试 `generation_result`。
- 下载优先使用 `remote_url`（公开文件域）；失败回退 `download_url`。
- 单镜失败不静默跳过，整个渲染任务标记失败，允许重试。

### 21.7 安全

- Token 只从 `.env` 读取，不写 SQLite、不返回 API、不写日志。
- `MCP_VIDEO_URL` 可在设置页显示；Token 仅显示"已配置"。
- 服务绑定 `127.0.0.1`；不要把 8000 端口暴露到公网。

### 21.8 实测结果

- MCP 连接：`initialize` + `tools/list` 成功，发现 34 个工具。
- 文生视频：4 秒 / 480p / 竖屏 → 480×864、4.46s、24fps、含音频。
- 图生视频：传入 1080×1920 封面 → 480×864、4.46s、24fps、含音频，输入图被记录为 `role=input`。
- 单镜归一化：MCP 片段 → 3.0s / 1080×1920 / 30fps / 含音频，叠加字幕与 AI 标识成功。
- 单镜端到端：`mode=mcp`，任务 ID 与 params 写入资产 meta。
- 5 镜完整成片：15.03s / 1080×1920 / 30fps / 含音频，manifest 记录 `video_provider=mcp`；演示包见 `data/demo_mcp/` 与 `data/demo_mcp_export.zip`。
- 全程耗时：5 镜渲染约 10 分钟（含轮询、归一化、拼接、封面）。

### 21.9 限制

- 480p 上采样到 1080×1920，近景质量可用但不等同原生 1080p。
- 单镜最低 4 秒，短镜头需裁切；长镜头通过补帧延长。
- MCP 任务为轮询模式，单镜约 90 秒；5 镜串行约 8–12 分钟。
- 依赖外部网关可用性、额度与模型策略；失败时回退到 Mock 需手动切换 `VIDEO_PROVIDER=mock`。

## 22. DeepSeek + REST 美术资源接入（v0.2）

### 22.1 Provider 矩阵

| 能力 | 变量 | 可选值 | 当前默认 |
|---|---|---|---|
| LLM | `LLM_PROVIDER` | `mock / deepseek / ark` | `deepseek` |
| 图片 | `IMAGE_PROVIDER` | `mock / rest / ark` | `rest` |
| 视频 | `VIDEO_PROVIDER` | `mock / rest / mcp / seedance` | `rest` |

- 三个 provider 独立切换，互不绑定。
- 设置页保存前会校验对应 Key/Token；缺失时返回明确错误。
- `AI_MODE` 仅作为展示/兼容标记，实际能力由 provider 决定。

### 22.2 DeepSeek LLM

- 接口：`POST https://api.deepseek.com/chat/completions`（OpenAI 兼容）。
- 鉴权：`Authorization: Bearer <DEEPSEEK_API_KEY>`。
- 模型：`deepseek-chat`（可在 `.env` 覆盖）。
- 任务：
  - 商品解析：根据商品名 + 描述输出 ProductBrief JSON。
  - 脚本分镜：根据 Brief + Skill 输出 VideoScript JSON。
- 约束：文本模型，不上传商品图；图片细节依赖描述质量。
- 解析：`parse_json_loose` 容错 Markdown/换行；服务端再做时长闭合与字段修复。
- 环境变量：

```dotenv
LLM_PROVIDER=deepseek
DEEPSEEK_API_KEY=...
DEEPSEEK_BASE_URL=https://api.deepseek.com
DEEPSEEK_MODEL=deepseek-chat
```

### 22.3 REST 美术资源

Base：`REST_ART_BASE_URL`；鉴权：`Authorization: Bearer REST_ART_TOKEN`。

| 接口 | 用途 |
|---|---|
| `POST /v1/capabilities/generation/image_generate` | 生成每镜无文字场景板 |
| `POST /v1/capabilities/generation/video_generate` | 以场景板 + 原图生成 4 秒视频 |
| `POST /v1/capabilities/generation/generation_job` | 轮询/推进任务 |
| `POST /v1/capabilities/generation/generation_result` | 获取结果与下载地址 |
| `POST /v1/capabilities/generation/generation_list` | 历史任务 / 连通性检查 |

**图片参数**

```json
{"aspectRatio": "portrait", "quality": "high"}
```

- 参考图：原产品图 data URL。
- 输出实测约 941×1672；服务端裁切/缩放到 1080×1920。
- 失败自动回退 Pillow 场景板，不阻断视频。

**视频参数**

```json
{"aspectRatio": "portrait", "resolution": "480p", "duration": 4}
```

- `aspectRatio`：`portrait / landscape / square`。
- `resolution`：`480p / 768p / 1080p`（以 Key/模型支持为准）。
- `duration`：1–15 秒；首版请求 `max(4, 镜头秒数)`，后期裁切/补帧。
- `images`：第一张场景板（首帧），第二张原产品图（参考）。
- 返回的 `download_url` 可直接匿名下载；`remote_url` 为公开文件域兜底。

### 22.4 新生产链路

```
DeepSeek：商品解析 → 脚本/分镜
  → Pillow：预演关键帧（便宜、快速）
  → REST image_generate：每镜无文字场景板
  → REST video_generate：场景板 + 原图 → 4 秒片段
  → FFmpeg normalize：裁到镜头时长、1080×1920/30fps
  → 字幕 PNG + AI 标识
  → concat → 封面 → ZIP
```

- 预演仍用 Pillow，避免 5 张 AI 图片的预演成本。
- 场景板在正式渲染时生成；每镜一次 image_generate。
- 图片失败回退 Pillow plate；视频失败则该镜任务失败，可整体重试。
- 设置页新增「测试 REST」与「测试 MCP」两个连通性按钮。

### 22.5 环境变量

```dotenv
LLM_PROVIDER=deepseek
DEEPSEEK_API_KEY=...
IMAGE_PROVIDER=rest
VIDEO_PROVIDER=rest
REST_ART_BASE_URL=...
REST_ART_TOKEN=...
REST_IMAGE_PARAMS={"aspectRatio":"portrait","quality":"high"}
REST_IMAGE_WAIT_SECONDS=30
REST_VIDEO_RESOLUTION=480p
REST_VIDEO_WAIT_SECONDS=30
REST_ART_TIMEOUT=1200
```

### 22.6 安全

- DeepSeek Key 与 REST Token 只从 `.env` 读取，不写数据库、不返回前端、不写日志。
- 设置页只显示“已配置/未配置”和公开 Base URL。
- 下载优先使用公开 `remote_url`，其次 `download_url`，避免把鉴权头发往文件域。

### 22.7 实测结果

- DeepSeek 解析：成功，返回 `source=deepseek`，卖点/价格解析正常。
- DeepSeek 脚本：成功，5 镜、总时长 15.0s，JSON 结构化。
- REST 图片：成功，`gpt-image-2`，941×1672。
